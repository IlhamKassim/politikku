Lesson 1: The Swing Model

Welcome to your first lesson on how the `live-political-analysis` repository models the Malaysian GE16 election.

1. The Problem

Predicting an election accurately per constituency is extremely hard. It usually requires granular demographic polling, historic precinct-level data, and expensive recurring operations. If we were to build a true predictive model, we would violate a core architectural rule: zero recurring cost (ADR 0002/0007).

2. The Solution: The Swing Model

Instead of a complex prediction engine, we use a Swing Model. Here is how it works:

  • The Baseline: We start with the hard facts: the GE15 federal election results for all 222 Seats.
  • The Input: We gather Sentiment purely from local, self-hosted analysis of news articles and periodic free poll reports (Merdeka Center).
  • The Application: We apply this Sentiment as a uniform swing across an entire state.
The Key Takeaway: If Sentiment suggests a 5% swing towards a Coalition in Johor, we simply add 5% to that Coalition's GE15 Baseline margin for every single seat in Johor.

3. Why use this specific model?

As documented in ADR 0001 and ADR 0005, this approach has massive architectural benefits:

  1. Transparency (It's just arithmetic): A Seat Call is never a bespoke, subjective judgement about a specific constituency. It is pure math: Baseline + State Swing.
  2. Falsifiability: Because we use uncalibrated, provisional constants to turn sentiment into a percentage swing (ADR 0003), we must present our results as a Projection, not a Prediction. It is honest about its limitations.
  3. Cost: It runs completely free, avoiding expensive APIs or complex demographic data purchases.
